# Workflows

| Workflow | Description |
|----------|-------------|
| [create-branches.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/create-branches.yml) | Creates the `staging` integration branch from the repository default branch (`main` or `master`) if it does not already exist. Idempotent; never modifies an existing branch. |
| [org-adr-consolidate.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-adr-consolidate.yml) | Reusable for the org docs repository (ideas.md 1). Gathers every repository's `docs/adr/` from `claude/repos.txt` of the org `.github` repo (or a given list) into `<out_dir>/<repo>/`, generates one index with status/date/ticket, and opens a PR in the calling repository. Also dispatchable here for a dry run. |
| [org-bootstrap.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-bootstrap.yml) | One-shot "make this repository conformant" (ideas.md 23). For a dispatched repository: seeds `staging`, applies the agent baseline (block, settings, MCP, skills, agents), writes a starter `org.toml`, `docs/adr/` skeleton, `flake.nix` on `lib.mkDevShell` and the org pipeline workflows where missing, generates CODEOWNERS, creates the standard labels, and opens one PR. Rulesets are applied when `ORG_ADMIN_TOKEN` exists. Idempotent; re-running on an old repository is the conformance fix. |
| [org-branch-guard.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-branch-guard.yml) | Reusable detect-and-revert for deploy branches on plans without rulesets (ADR-007). On every push to a deploy branch it checks the new commit is the merge of a pull request; a direct push gets a revert PR, an issue naming the pusher, a metrics event, and never releases or deploys (the release and deploy workflows verify the same thing). Force-pushes are caught the same way. Call from a consuming repo on `push: branches: [main, master]`. Needs `pull-requests: write` and `issues: write`. |
| [org-branch-sweep.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-branch-sweep.yml) | Branch ↔ ticket sweep (ADR-008, INFRA-278). Lists the branches of every repository in `claude/repos.txt` (or the whole org with `all`), extracts Jira keys from branch names, correlates them with ticket summary / status / assignee, and reports per owner what is pending merge — ahead/behind the integration branch, last-commit age, open PR, and flags (`merged`, `ticket-done`, `stale`, `no-ticket`, `unassigned`). Written to the job summary and an artifact; on the schedule (or `publish: issue`) it also refreshes the pinned issue labelled `branch-sweep` in this repository. Needs a token that can read every swept repository (`ORG_SYNC_TOKEN` or `ORG_READ_TOKEN`; the default token only reads this one), plus `JIRA_EMAIL` / `JIRA_API_TOKEN` secrets and the `JIRA_BASE_URL` variable (or `[jira].base_url` in this repo's org.toml) for the ticket columns. Same script locally: `jira sweep` (subagent `org-branch-sweep`). |
| [org-deploy.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-deploy.yml) | Reusable deploy (ADR-003, R9/R10). Reads `deploy.<environment>` from the caller's `org.toml`; for a production-class environment first verifies the commit is an approved, gated, code-owner-reviewed merge (ADR-007), then runs the declared command on the declared runner labels inside the declared GitHub Environment (its required reviewers are the named approver set), then polls the declared health URL/command. A failed health check on a production-class environment opens a rollback PR to the previous release tag — proposed, never merged automatically. Call with `environment: staging` on push to the integration branch and `environment: production` after a release. No `deploy.<environment>` in org.toml → the run is a no-op with a notice. |
| [org-gate.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-gate.yml) | Reusable verification gate (ADR-003, R1–R3). Reads the caller repository's `org.toml`, picks the tier (fast for the integration branch, full for a PR into a deploy branch), installs nix when declared, and runs the repository's own gate command. The check is named `gate` so rulesets can require it. Call from a consuming repo's workflow on pull_request and on push to the integration branch. Pass `secrets: inherit`; set `ORG_READ_TOKEN` if the org `.github` repository is private. |
| [org-guardrails.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-guardrails.yml) | Reusable deterministic guardrails for a pull request (ADR-003, R4/R8/R9): secrets scan (org patterns + gitleaks), commit ticket prefixes, provenance labels (`author:*`), PR hygiene (size, one ticket, Verification section, ADR-required paths, generated files), supply chain (pinned actions, new-dependency registry check). Each job is a stable check name (`secrets`, `commits`, `provenance`, `pr`, `supply-chain`) so rulesets can require them. Same scripts run locally from `.claude/hooks/org/`. |
| [org-oci.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-oci.yml) | Reusable artifact publish (ideas.md 26). Builds the OCI image the caller's `org.toml` declares (`[artifacts.oci] attr`) with nix and pushes it to the declared registry as `<registry>/<owner>/<repo>:<tag>` (plus `:latest` on a release). The same Nix declaration that deploys a closure produces the image, so developers can `docker run` what production runs. Call after the gate on the integration branch (tag = short SHA) and after a release (tag = the release tag). No `[artifacts.oci]` → no-op. |
| [org-platform-github.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-platform-github.yml) | The org's GitHub configuration as code (ADR-010), run from this repository (ADR-011). On a PR touching `nix/github/**`, `claude/repos.txt` or `claude/rulesets/**` it renders the `platform.github` Terranix stack and posts the OpenTofu plan as a PR comment; on push to `main` it applies (kill-switched; feature-test mode plans only). State lives in the S3 bucket named by `ORG_TF_STATE_BUCKET` (apply refuses local state). Token from `ORG_ADMIN_TOKEN`; Actions secret values, if managed, from `ORG_TF_SECRETS` (JSON). Runs on `vars.ORG_RUNNER` (the fleet runner label) when set, else `ubuntu-latest`; the Nix installer step only runs on hosted runners. Same command locally: `nix run .#platform-github -- plan`. |
| [org-rulesets.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-rulesets.yml) | Branch protection as code (ADR-003, R5/R9). Applies `claude/rulesets/*.json` to every repository in `claude/repos.txt` (or a dispatched subset): deploy branches PR-only with required checks `gate / gate` and `guardrails / *`, code-owner review, no force-push or deletion; the integration branch protected against rewrites only. Diffs before writing; weekly drift correction. Needs `ORG_ADMIN_TOKEN`. |
| [org-runner-smoke.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-runner-smoke.yml) | Canary for the runner policy (ADR-011). Picks the runner exactly as the trusted org-level jobs do (`vars.ORG_RUNNER`: unset → hosted, `auto` → fleet when online, else the given label), then proves the job environment: where it ran, the tools the org workflows need (nix, python3, jq, gh), and that the `platform.github` stack renders there. Weekly, and dispatched by the runner bootstrap as its final step. |
| [org-scorecard.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/org-scorecard.yml) | Weekly conformance scorecard (ideas.md 10). Runs `org-check` and the agent-config sync check against every repository in `claude/repos.txt`, writes one row per repository to `SCORECARD.md`, and opens/updates a PR in this repository with the result. Needs `ORG_SYNC_TOKEN` (read on the targets, write here). |
| [promote-pr.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/promote-pr.yml) | **DEPRECATED (ADR-002, INFRA-262)** — v1 branch promotion (main→dev→qa→prod) that only checks for merge conflicts. Kept working for existing `@v1` callers; emits a deprecation warning on every run. Do not adopt in new repositories. |
| [rollback.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/rollback.yml) | Opens a rollback PR that restores the deploy branch to a previous release tag (v2 model, INFRA-276). Proposed, never merged automatically; merging it is a release like any other. Dispatch with the target tag, or leave it empty for the previous release. |
| [sync-agent-config.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/sync-agent-config.yml) | Distributes the org agent baseline (`claude/`) to every repository in `claude/repos.txt`: inserts or refreshes the managed BEGIN/END block at the top of the repo's CLAUDE.md, merges `.claude/settings.json` and `.mcp.json`, and opens (or updates) one PR per repo when anything changed. Runs on push to `main` touching `claude/`, weekly as a drift check, and on dispatch (optionally dry-run or for a subset of repos). Needs the `ORG_SYNC_TOKEN` secret. |
| [sync-release.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/sync-release.yml) | Publishes a release when a PR merges into `main` or `master`: computes the next semver, tags the merge commit, and creates a GitHub Release with the changelog since the previous tag. Refuses to run for any other event or base branch, so a direct push never releases; then verifies the merged PR had a non-author approval and the required org check runs (the ADR-007 substitute for rulesets). Then opens a back-merge PR into the integration branch and, when an API key and model variable exist, appends agent-drafted release notes. Reusable (`workflow_call`, outputs `tag`) and dispatchable on a deploy branch. |
| [template-cleanup.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/template-cleanup.yml) | Manual one-shot cleanup for a repository created from this template via the "Use this template" button. Dispatch it from the Actions tab in the generated repository (guarded so it does nothing in a template repository): it runs `.github/scripts/template-init.sh` to strip the template's own `docs/adr/` history, leave an empty ADR skeleton, and commit the result. Idempotent — a marker makes reruns no-ops. The sanctioned path for a tailored `.github` is `claude/construct.py`; this workflow only serves the raw-copy button path. Equivalent locally: `bash .github/scripts/template-init.sh`. |
| [version-and-package-source.yml](https://github.com/jeirslab/dot-github/blob/main/.github/workflows/version-and-package-source.yml) | Reusable workflow for semantic versioning, tagging, and GitHub Release creation with flexible configuration. |
